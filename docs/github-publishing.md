# 🚀 GitHub publishing checklist

> 🐙 **Canonical repository:**
> [akunopaka/smart-e-tape-measure-web-bluetooth](https://github.com/akunopaka/smart-e-tape-measure-web-bluetooth)

GitHub uses repository names, descriptions, README content, and topics to help
people understand and discover projects. Keep the public metadata broad enough
for anyone searching for a smart tape measure, while naming the tested hardware
as evidence rather than as the whole identity of the project.

## 🏷️ Repository name

```text
smart-e-tape-measure-web-bluetooth
```

## ✍️ Description

```text
Open-source Web Bluetooth explorer for smart tape measures: decode BLE GATT packets, capture live and confirmed measurements, and document device protocols. Tested with RF-BMF01 / ES-Tape.
```

hardware category, research method, and implementation language without turning
the topic list into keyword soup.

## ✅ Before making it public

- confirm that the setup and live interface screenshots contain no sensitive data;
- confirm that `docs/device-photo.jpg` shows the tested hardware clearly;
- confirm that exported captures, email addresses, device identifiers, and local
  paths are not committed;
- enable GitHub Pages from `main` and `/(root)` if a live demo is useful;
- add the description and topics above in the repository's **About** settings;
- use the live interface screenshot as the social preview image.

The README already leads with the phrases people are likely to search for:
`smart Bluetooth tape measure`, `Web Bluetooth`, `BLE`, `GATT`, `digital
measuring tape`, and `protocol reverse engineering`. That is enough; repeating
them everywhere would sound like a robot trying to sell a ruler. 📏
